# Turnirium 1.1.0

Локальное веб-приложение для небольших любительских HEMA-турниров. Один основной компьютер запускает сервер и хранит SQLite-файл, остальные рабочие места секретарей, табло и общий экран подключаются к нему по локальной сети через браузер.


## Изменения 1.1.0 — production refactor

- backend разделён на компактные предметные сервисы и тематические HTTP-router модули; старые крупные `engine.py` и `api.py` превращены в небольшие фасады/агрегаторы;
- клиентский JavaScript разделён по экранам и предметным областям, включая отдельный модуль категорий и сеток;
- WebSocket-инфраструктура вынесена отдельно, lifecycle FastAPI переведён на современный `lifespan`;
- добавлена строгая серверная валидация правил категории, счёта и причин завершения;
- исправлены пограничные ошибки с ничьёй в олимпийке, пустым победителем, произвольным `delta` счёта и изменением таймера завершённого боя;
- все поясняющие комментарии в исходном коде приведены к русскому языку;
- добавлены `docs/ARCHITECTURE.md`, `docs/DEVELOPMENT.md` и `REFACTOR_REPORT.md`;
- добавлен архитектурный тест против повторного появления монолитных модулей на тысячи строк;
- генерация/редактирование этапов вынесены из CRUD категорий в отдельный `category_stages.py`, а критические функции и классы ограничены автотестом по размеру;
- исправлены обход блокировки текущего боя секретаря через прямой выбор, устаревшая ссылка площадки при переносе выбранного боя и некорректные перестановки очереди;
- сравнение правил категории после первого боя теперь семантическое: старый формат JSON не мешает переименовать категорию без изменения спортивных правил;
- посев категории отклоняет дубликаты и чужие ID вместо тихого сохранения неоднозначного порядка;
- импорт участников стал транзакционным, валидирует статусы, ограничивает размер входа и корректно применяет выбытие к уже созданным боям;
- добавлены статические smoke-тесты SPA/API и дополнительные проверки транзакционных пограничных сценариев.

Подробности: [`REFACTOR_REPORT.md`](REFACTOR_REPORT.md) и [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Что реализовано

- участники: фамилия, имя, клуб/команда, **город** и статус `Активен / Выбыл`;
- редактирование карточки участника без удаления и повторного ввода;
- импорт списка участников из **CSV / JSON** и экспорт списка в **CSV / JSON**;
- статус **Выбыл**: спортсмен исключается из новых жеребьевок, а уже определённые будущие соперники получают проход с соответствующей причиной;
- категории со своими правилами: длительность боя, сигнал до окончания, произвольный набор кнопок изменения счёта;
- для групп и Swiss настраиваются турнирные очки **за победу и за ничью**, а секретарь может явно зафиксировать ничью;
- создание категории выполняется в одном редакторе: все правила задаются до нажатия «Создать категорию»;
- до начала первого реального боя категории можно менять формат и все правила; структурные изменения безопасно сбрасывают только ещё не начатую сетку, сохраняя участников;
- встроенные в редактор локальные **шаблоны правил**: применение, сохранение из текущих значений формы и удаление без отдельного экрана управления;
- завершение категории и турнира с переносом в архив;
- при завершении категории/турнира формируются **PDF** и **JSON** результатов;
- предупреждения внутри боя (`warning`, `score_penalty`, `forfeit`) и накопительный лимит предупреждений с дисквалификацией;
- олимпийская сетка с BYE, финалом и **боем за 3-е место**;
- группы с настраиваемым желаемым размером, количеством выходящих в плей-офф и отдельным боем за 3-е место в плей-офф;
- швейцарская система по турам; туры у организатора расположены вертикально, а пары внутри каждого тура адаптивно переносятся по ширине, поэтому большое число туров не раздувает экран горизонтально;
- автоматическое разведение участников одного клуба, затем по возможности одного города;
- явная фиксация этапа: группы и каждый Swiss-тур сначала формируются в режиме редактирования и начинают учитываться в расписании только после кнопки **«Начать…»**;
- ручное drag-and-drop перемещение участников внутри групп и между группами до их первого проведённого боя;
- ручное drag-and-drop изменение ещё не начатых пар текущего Swiss-тура;
- ручное drag-and-drop перемещение участников между ветвями первого раунда олимпийки/плей-офф до начала соответствующего этапа;
- зеркальная к финалу турнирная сетка с соединительными линиями и карточками участников;
- PDF категории содержит не только протокол результатов, но и **зеркальную графическую схему сетки** с финалом и бронзовым боем;
- общий экран показывает аккуратную зеркальную сетку, групповые таблицы, результаты, текущие площадки и обычные часы;
- несколько площадок и независимые очереди поединков;
- drag-and-drop расписание между площадками;
- автоматическое назначение готовых боёв, если активна одна площадка;
- настраиваемое **разведение повторных выходов**: генератор очереди старается оставлять заданное число других боёв между двумя выходами одного спортсмена; ограничение мягкое, неизбежные конфликты помечаются, а очередь можно переоптимизировать одной кнопкой;
- отдельный интерфейс секретаря площадки;
- победа по счёту и отдельное **техническое поражение**;
- **корректировка уже завершённого боя** из интерфейса организатора или секретаря: счёт, предупреждения и итог можно исправить с записью изменения в журнал; зависимые сетки пересчитываются безопасно;
- нижние вкладки секретаря `Очередь по сетке / Сетка / Группы`;
- отдельное полноэкранное табло площадки с таймером, предупреждениями и следующим боем;
- общий информационный экран с плавным локальным отсчётом таймеров и синхронизацией с сервером;
- WebSocket-синхронизация + резервный периодический refresh;
- SQLite в WAL-режиме, резервное копирование через SQLite backup API;
- сервисная очистка БД с резервной копией перед удалением;
- корректное закрытие WebSocket и подавление ожидаемого Windows `WinError 10054` при закрытии вкладки;
- ненавязчивый **брендинг из отдельного `branding.json`**;
- простое **desktop-окно сервера** со статусом, LAN-адресами, выбором площадки и кнопками открытия основных экранов;
- сворачивание крестиком или отдельной кнопкой в **системный трей**;
- контекстное меню трея: развернуть, организатор, общий экран, секретарь, табло площадки, полный выход;
- автоматический опрос активных IPv4-интерфейсов Wi-Fi/Ethernet и отображение прямых LAN-ссылок;
- монитор подключенных браузеров: IP, тип открытого экрана, площадка и время подключения;
- отдельная вкладка **Сеть** у организатора с теми же LAN-адресами и текущими подключениями;
- упаковка в один Windows EXE через PyInstaller.

## Совместимость со старой базой

При первом запуске 0.7 существующая `data\tournament.db` мигрируется автоматически. К турниру добавляются настройки порядка боёв (`разводить повторные выходы` и желаемый промежуток), старые базы получают безопасные значения: функция включена, промежуток 1 бой. Все ранее добавленные поля и результаты сохраняются.

Перед обновлением всё равно рекомендуется сохранить папку `data` или сделать резервную копию из интерфейса.

## Запуск из PyCharm

Рекомендуется использовать отдельное виртуальное окружение проекта.

```bat
cd C:\Users\User\PycharmProjects\Turnirium_project
python -m pip install -r requirements.txt
python run.py
```

Если PyCharm запускает проект интерпретатором из другого проекта, выберите в `Settings -> Project -> Python Interpreter` окружение `Turnirium_project\.venv`.

При обычном запуске появится небольшое окно **Turnirium - сервер**. Сервер стартует автоматически; из окна можно открыть организатора, общий экран, секретаря и табло выбранной площадки.

Крестик не завершает турнирный сервер, а сворачивает окно в системный трей. Для полного завершения используйте **Полностью выключить** в окне или **Полностью выйти** в меню трея.

Если нужен старый режим только с сервером/консолью (например, для диагностики):

```bat
python run.py --server-only
```

В этом режиме `--no-browser` отключает автоматическое открытие организаторского интерфейса.


## Desktop-окно, трей и сеть

Обычный запуск `python run.py` на Windows показывает управляющее окно сервера. В нём доступны:

- зелёный/жёлтый индикатор состояния Uvicorn;
- локальный адрес и все найденные LAN IPv4-адреса;
- прямые ссылки на организатора, общий экран, секретаря и табло выбранной площадки;
- выбор площадки для кнопок секретаря/табло;
- список активных браузерных экранов с IP, типом экрана, площадкой и временем подключения;
- сворачивание в трей и полное выключение.

В системном трее доступны те же основные действия. Кнопки секретаря и табло используют площадку, выбранную в desktop-окне; если площадка одна, она выбирается автоматически.

У организатора есть отдельная вкладка **Сеть**. Она показывает все активные сетевые интерфейсы и прямые LAN URL, а также текущие WebSocket-подключения. Один компьютер может отображаться несколькими строками, если на нём одновременно открыты, например, секретарь и табло.

Для доступа с других компьютеров Windows Firewall должен разрешать входящие подключения к выбранному порту (по умолчанию `8000`) для `Turnirium_1.1.exe`.

## Разведение повторных выходов

На вкладке **Площадки** есть блок `Порядок боёв`:

- `Разносить повторные выходы` - включает мягкое ограничение;
- `Других боёв между выходами` - желаемый промежуток от 1 до 10;
- `Оптимизировать текущую очередь` - вручную перестраивает еще не начатые бои каждой площадки.

При одной площадке новые готовые бои сразу назначаются в порядке, который по возможности не ставит одного спортсмена подряд. Уже вручную выставленная очередь сама по себе при каждом обновлении страницы не перемешивается. Если математически невозможно соблюсти заданный промежуток, приложение оставляет лучший найденный порядок и помечает близкий повторный выход предупреждением.

## Экраны

- `/admin` - организатор;
- `/mat/<id>` - секретарь площадки;
- `/board/<id>` - табло площадки;
- `/public/<tournament_id>` - общий телевизор.

Для другого компьютера в той же LAN/Wi-Fi используется IP главного ПК, например:

```text
http://192.168.1.100:8000/mat/2
http://192.168.1.100:8000/board/2
```

Разрешите `Turnirium_1.1.exe` входящие подключения в Windows Firewall для **частной сети**.

## Брендинг

В корне проекта находится отдельный файл:

```text
branding.json
```

Пример:

```json
{
  "app_name": "Открытый кубок клуба",
  "developer_club_name": "СК Пример",
  "developer_club_url": "https://example.org",
  "show_footer_branding": true
}
```

Параметры:

- `app_name` - название приложения/системы в интерфейсе и метаданных PDF;
- `developer_club_name` - небольшая подпись разработчика/клуба внизу всех экранов;
- `developer_club_url` - ссылка на клуб; если начинается с `http://` или `https://`, подпись становится кликабельной;
- `show_footer_branding` - можно полностью скрыть нижнюю подпись.

`branding.json` включается в PyInstaller-сборку. Кроме того, файл с тем же именем, положенный **рядом с готовым EXE**, имеет приоритет: так можно менять название и ссылку без пересборки программы.

В стандартном файле URL намеренно пустой, чтобы тестовая сборка не вела на фиктивный сайт.

## Импорт и экспорт участников

Во вкладке **Участники** доступны:

- `Экспорт CSV`;
- `Экспорт JSON`;
- `Импорт списка`.

Рекомендуемый CSV - UTF-8, разделитель `;`:

```text
Фамилия;Имя;Клуб;Город;Статус
Иванов;Иван;Спарта;Москва;Активен
Петров;Пётр;Витязь;Тула;Активен
```

Также распознаются английские заголовки `last_name`, `first_name`, `club`, `city`, `status`, а разделитель CSV определяется автоматически (`;`, `,` или табуляция).

JSON может быть либо массивом участников, либо объектом вида:

```json
{
  "participants": [
    {
      "last_name": "Иванов",
      "first_name": "Иван",
      "club": "Спарта",
      "city": "Москва",
      "status": "active"
    }
  ]
}
```

Совпадающие записи определяются по сочетанию `фамилия + имя + клуб + город`: они обновляются, а не дублируются.

## Порядок групп и Swiss

Генерация и старт теперь разделены намеренно.

### Группы

1. Нажать **Сформировать**.
2. Проверить состав групп.
3. При необходимости перетащить участников между группами.
4. Нажать **Начать групповой этап**.
5. После этого состав фиксируется, а бои становятся доступными площадкам.
6. Кнопка **Создать плей-офф** появляется только после завершения всех групповых боёв.

### Swiss

1. Нажать **Сформировать тур 1**.
2. До старта тура можно перетаскивать участников между парами текущего тура.
3. Нажать **Начать тур 1**.
4. Пары фиксируются и попадают в расписание.
5. После завершения всего тура появляется кнопка формирования следующего.

Так секретарь не получит на площадку бой из ещё редактируемой жеребьёвки.

## Бой за 3-е место

Для олимпийской системы и плей-офф при наличии двух полуфиналов автоматически создаётся отдельный бронзовый бой. В него после полуфиналов попадают проигравшие. Он отображается:

- в сетке организатора;
- у секретаря и в расписании;
- на общем экране;
- в итоговом PDF;
- в JSON-экспорте.

## PDF и JSON результатов

При завершении категории или турнира приложение подготавливает экспорт. Его также можно скачать повторно из архива.

PDF категории включает:

- итоговые места;
- графическую зеркальную сетку относительно финала;
- бой за 3-е место;
- таблицу всех проведённых боёв;
- групповые таблицы, если формат начинается с групп.

JSON является техническим снимком с `schema_version` и предназначен для архива/внешней обработки.

Файлы сохраняются в:

```text
data\exports\
```

## Сборка одного EXE в Windows / PyCharm

PyInstaller не кросс-компилирует Windows EXE из Linux/macOS, поэтому итоговый Windows-файл собирается на Windows.

В терминале PyCharm:

```bat
build_windows.bat
```

Скрипт создаёт/использует `.venv`, устанавливает зависимости и PyInstaller, затем собирает:

```text
dist\Turnirium_1.1.exe
```

На компьютере турнира Python не требуется.

Рядом с EXE будут использоваться:

```text
data\
  tournament.db
  backups\
  exports\
branding.json     # необязательный внешний override брендинга
```

Практичнее держать приложение, например, в `C:\Tournament`, а не в `Program Files`, чтобы Windows не мешал записи локальной БД.

Для диагностики есть `build_debug_windows.bat`.

## Типовой порядок работы

1. Запустить приложение на основном компьютере.
2. Создать турнир; площадка №1 появится автоматически.
3. Добавить участников вручную или импортировать CSV/JSON.
4. Создать категории, при необходимости загрузив ранее сохранённый шаблон.
5. Добавить участников в категории.
6. Сформировать сетку/группы/Swiss-тур.
7. Проверить жеребьёвку и вручную скорректировать её drag-and-drop.
8. Для групп или Swiss явно нажать **Начать…**.
9. При одной площадке готовые бои назначатся автоматически; при нескольких распределить их во вкладке **Площадки**.
10. Открыть рабочие места секретарей `/mat/<id>`.
11. Открыть табло `/board/<id>` и один раз включить звук.
12. При необходимости вывести `/public/<tournament_id>` на общий телевизор.
13. Завершить категорию, скачать/проверить PDF и JSON.
14. После мероприятия завершить турнир и сохранить итоговые экспорты/backup.

## Завершение, архив и очистка

- **Завершить категорию** - категория исчезает из активных и остаётся в архиве.
- **Завершить турнир** - турнир перемещается в архив; его незакрытые категории также закрываются.
- Архив открывается в режиме просмотра; возврат в работу выполняется отдельной кнопкой.
- Вкладка **Сервис** содержит backup и очистку БД.
- Перед очисткой автоматически создаётся резервная копия.
- Для очистки требуется ввести слово `ОЧИСТИТЬ`.
- Шаблоны категорий можно сохранить при очистке.

## Данные и сеть

Все браузеры работают через HTTP/WebSocket. Только главный процесс приложения открывает SQLite.

**Не размещайте `tournament.db` в общей сетевой папке для прямого доступа нескольких компьютеров.** По сети должны идти только HTTP/WebSocket-запросы.

## Ограничения

Проект ориентирован на небольшие местные соревнования, поэтому намеренно не содержит облачных аккаунтов, онлайн-платежей и сложной федерационной инфраструктуры.

Swiss pairing остаётся упрощённым: турнирные очки и запрет повторной пары имеют приоритет, затем учитываются клуб и город. Перед стартом текущего тура организатор может вручную переставить участников. Значения очков за победу и ничью задаются в правилах категории.

При исправлении старого результата приложение защищает зависимые этапы: не начатый плей-офф после правки группового боя сбрасывается для повторного формирования; не проведённые последующие Swiss-туры удаляются и формируются заново. Если смена победителя в олимпийской ветке затрагивает уже начатый следующий бой, исправление блокируется до корректировки более поздних результатов в обратном порядке.

## Windows: WinError 10054

При резком закрытии браузерной вкладки Windows может сообщать о `ConnectionResetError: [WinError 10054]`. В актуальной версии клиент корректно закрывает WebSocket при уходе со страницы, а сервер игнорирует только ожидаемые коды 10053/10054 в обработчике event loop. Остальные ошибки не подавляются.
