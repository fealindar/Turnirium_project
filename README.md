# Turnirium 1.1.4

Поучаствовав в нескольких турнирах, в которых в 2026 году составление сетки велось на бумажках, а табло было перекидным - я понял что сообществу может пригодиться инструмент для автоматизации подобных задач. Эдакий хемагон для бедных и маленьких, не требующий интернета для своей работы. Поэтому отложив саблю в угол я сел и запилил следующее приложение.

Turnirium — локальное приложение для проведения небольших HEMA-турниров. Один компьютер запускает сервер и хранит SQLite-базу, остальные рабочие места открываются в браузере по локальной сети.

При использовании приложения просьба сохранять ссылку на клуб разработчика: Рейд, г. Донецк - https://vk.ru/hema_dn
Пожелания, предложения и обратную связь можно отправлять туда же.
Свежие версии будут храниться в  https://github.com/fealindar/Turnirium_project/tree/master/dist

## Что умеет

- участники, категории и посев;
- олимпийская система, группы + плей-офф, швейцарская система и «все со всеми»;
- несколько площадок с общей очередью боёв;
- отдельные экраны организатора, секретаря, табло и общий экран турнира;
- счёт, таймер, предупреждения и исправление завершённого боя;
- PDF/JSON-экспорт результатов, CSV/JSON-импорт и экспорт участников;
- резервные копии и переключение рабочих SQLite-баз.

## Запуск из исходников

Нужен Python 3.11+.

```bash
python -m venv .venv

```

Windows:

```bat
.venv\Scripts\activate
pip install -r requirements.txt
python run.py
```

Linux/macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

По умолчанию интерфейс организатора доступен по адресу `http://127.0.0.1:8000/admin`. Адреса для других компьютеров в сети показаны во вкладке **Сеть**.

Для запуска без desktop-окна:

```bash
python run.py --server-only
```

## Windows-сборка

```bat
build_windows.bat
```

Зависимости для сборки перечислены в `requirements-build.txt`. Один запуск `build_windows.bat` по умолчанию создаёт в `dist` **два релизных варианта** с версией из `app/version.py` в имени:

- `Turnirium_v1.1.4.exe` — PyInstaller **onefile**;
- `Turnirium_v1.1.4.zip` — PyInstaller **onedir + noarchive**, уже упакованный в ZIP. После распаковки ZIP получается каталог `Turnirium_v1.1.4\` с одноимённым EXE и `_internal`.

Версия `1.1.4` здесь приведена для текущего релиза; имена следующих сборок меняются автоматически вместе с `APP_VERSION`. UPX, custom runtime hooks и нестандартный `runtime_tmpdir` не используются. Для `onefile` сохраняется стандартный PYZ (`noarchive=False`), а второй вариант специально собирается с `noarchive=True`.

Если важна минимизация ложных срабатываний Microsoft Defender/SmartScreen, предпочтительнее распространять ZIP с **onedir + noarchive**: он не использует onefile self-extraction. Onefile оставлен как удобный переносимый вариант, но сам формат self-extracting executable статистически чаще попадает под ML/эвристические проверки. Сборщик не применяет обфускацию, UPX или нестандартные загрузчики.

Для публичных релизов поддерживается опциональная Authenticode-подпись. Установите сертификат code-signing в Windows Certificate Store и задайте `TURNIRIUM_SIGN_CERT_SHA1` и `TURNIRIUM_TIMESTAMP_URL`; тогда сборщик подпишет основной EXE обоих вариантов через `signtool.exe` и проверит подпись перед упаковкой ZIP. Подпись повышает доверие к происхождению файла, но не является гарантией отсутствия антивирусных срабатываний.

Перед PyInstaller скрипт автоматически генерирует `version_info.txt` из `app/version.py`, поэтому PE VERSIONINFO содержит ProductName, FileDescription, FileVersion, ProductVersion и versioned `OriginalFilename`.

## Данные

Рабочая база по умолчанию находится в `data/tournament.db`. Для переноса турнира между компьютерами лучше использовать встроенную резервную копию, а не копировать открытую БД вручную.
