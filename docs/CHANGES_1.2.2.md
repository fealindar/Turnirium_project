# Turnirium 1.2.2 — переключатель «Отзеркалить табло»

Версия **1.2.2** основана на **1.2.1** и сохраняет изменения предыдущих релизов, включая посев группового плей-офф.

## Назначение

Когда ноутбук секретаря и зрительское табло направлены в разные стороны, зрители должны видеть красного и синего бойцов с правильной визуальной стороны. Для этого вводится переключатель **«Отзеркалить табло»** в **центре верхней панели секретаря**. Он всегда доступен — до боя, во время его проведения, после завершения боя и при пустой площадке.

По умолчанию выключен: красный слева, синий справа. При включении на **зрительском табло** красный отображается справа, синий — слева. Меняются местами **целиком блоки** участников с их именами, клубами, городами, очками, предупреждениями и цветовыми фонами. Очередь «Следующий бой» на табло также отображается в зеркальном порядке. Сам экран секретаря не зеркалируется.

Переключатель действует немедленно в обе стороны, без остановки таймера, смены боя или перезагрузки табло (передача события по WebSocket; периодическая загрузка состояния сохранена для надёжности). Настройка хранится в SQLite **для каждой площадки внутри конкретного турнира** и восстанавливается после обновления страницы/переподключения. Изменение на одной площадке не меняет другую.

## Изменения реализации

- `Area.board_mirrored: bool`, по умолчанию `false`.
- Автоматическая идемпотентная миграция существующих SQLite-файлов: `areas.board_mirrored BOOLEAN NOT NULL DEFAULT 0`. Существующие поединки и результаты не изменяются.
- `GET /api/areas/{area_id}/state` теперь содержит `area.board_mirrored`.
- `PUT /api/areas/{area_id}/board-mirror` принимает `{"mirrored": true/false}` строго как JSON boolean; пишет аудит `AREA_BOARD_MIRROR_CHANGED` только при реальном изменении и рассылает `area_changed`.
- Секретарь: неизменный верхний переключатель, видимый при отсутствии боя; ошибка записи возвращает его в предыдущее состояние.
- Табло: перестановка полных цветовых блоков; никаких изменений в логических сторонах `red/blue`, победителях, предупреждениях или результатах.
- Версия приложения и ресурсов Windows обновлена до `1.2.2`.

## Установка и миграция

**Способ 1 — полный архив:** распаковать `Turnirium_1.2.2_sources.zip` вместо исходников предыдущего релиза, **не заменяя** рабочий каталог данных (`data`) и не затрагивая активную SQLite-базу.

**Способ 2 — патч строго поверх исходников 1.2.1:**

```bash
git apply --check /путь/к/Turnirium_1.2.1_to_1.2.2.patch
git apply /путь/к/Turnirium_1.2.1_to_1.2.2.patch
```

Перед установкой **закройте приложение и сделайте резервную копию рабочей БД**. При запуске новой версии добавляется одно поле в таблицу `areas`; откат только исходников к 1.2.1 не удаляет это поле (оно останется безвредным для предыдущей версии).

Полный архив — **исходники, без готового Windows exe**. Для exe используйте штатную процедуру сборки проекта.

## Проверки

```bash
python -m pytest -q -W error
python -m compileall -q app tests
for file in app/static/*.js; do node --check "$file"; done
```

Автотестами проверяются: независимость площадок и турниров, сохранение SQLite, многократное переключение, отсутствие изменений активного боя, валидация API, миграция старой схемы, WebSocket-уведомления, корректный порядок цветовых блоков/очков/предупреждений и предпросмотр следующего боя.
