# Turnirium 1.1.7 — исправления к 1.1.6

## Площадки

- Список **«Несколько площадок»** вынесен в отдельный слой `document.body`, поверх
  горизонтально прокручиваемых карточек. Позиция ограничивается экраном; список
  закрывается при повторном нажатии, клике снаружи, Escape или смене размера окна.
  После закрытия его можно открыть вновь. Фоновый периодический опрос не прерывает
  уже открытый список.
- Ручное распределение готовых поединков между несколькими площадками теперь
  **приоритетно выравнивает количество боёв**, а затем подбирает порядок, который
  уменьшает повторные выходы бойцов внутри одной и между несколькими площадками.
  Например, 12 готовых боёв на двух пустых площадках распределяются 6/6.
- **«Оптимизировать очереди»** доступна независимо от настройки интервалов отдыха.
  Кнопка умеет *не только упорядочивать*, но и перераспределять назначенные,
  ещё не начавшиеся бои **между всеми включёнными площадками**.
- Не переносятся выбранный текущий бой, идущие и завершённые бои, бои отключённых
  площадок и нераспределённые бои. Запланированные (`pending`) бои, уже назначенные
  на площадки, могут быть переставлены. Изменение ручного назначения возможно
  только после явного нажатия «Оптимизировать очереди».
- В API `POST /api/tournaments/{id}/schedule-optimize` дополнительно возвращаются
  `moved_matches`, `cross_area_conflicts`, `area_loads` (ID площадки → число боёв).
  `unavoidable_conflicts` сохранён для совместимости; если разведение повторных
  выходов выключено, это поле равно нулю.

**Оценка времени**: когда известен только порядок боёв, а не фактическое расписание
их начала, синхронность оценивается по позициям в очередях. Полностью исключить
все межплощадочные пересечения невозможно при повторяющихся участниках, но
распределитель по возможности снижает их количество без перекоса 10/2.

## Обоюдные исходы

В форме исправления завершённого боя появились отдельные категории результата:

| Код API | Текст |
| --- | --- |
| `DOUBLE_FORFEIT` | Обоюдное поражение (также для смешанных санкций) |
| `DOUBLE_TECHNICAL_LOSS` | Обоюдное техническое поражение |
| `DOUBLE_WARNING_FORFEIT` | Обоюдное поражение по предупреждениям |
| `DOUBLE_DISQUALIFICATION` | Обоюдная дисквалификация |
| `DOUBLE_WITHDRAWAL` | Обоюдное выбытие |

В каждом случае `winner_cp_id=null` (победителя нет). Обе стороны получают
по одному **поражению**, **не получают турнирные очки за победу или ничью**;
при этом счёт каждой стороны, число проведённых боёв, разница и набранные очки
учитываются в итоговых и промежуточных таблицах, включая олимпийскую стадию.

При завершении боя секретарём тип одинаковых санкций обеих сторон теперь
автоматически даёт соответствующую уточнённую категорию. Старый код
`DOUBLE_FORFEIT` сохранён для чтения старых результатов и совместимости клиентов.
При исправлении можно вручную выбрать любую обоюдную категорию; изменение
сохраняется в аудите и не конвертируется в победу одной стороны.

В PDF-выгрузке сохранено читаемое название результата.

## Обновление

Полный архив исходников 1.1.7 и патч **строго от исходников 1.1.6** являются
альтернативными способами обновления. Сначала сделайте резервную копию БД.
Миграции схемы SQLite нет: используются существующие строковые поля причин
поединков. Патч можно применить из корня проекта:

```bash
git apply --check /путь/к/Turnirium_1.1.6_to_1.1.7.patch
git apply /путь/к/Turnirium_1.1.6_to_1.1.7.patch
```

Содержимое патча проверяется применением к чистой копии исходников 1.1.6;
исходники пакуются без дистрибутивов, кэшей и рабочих данных SQLite.
