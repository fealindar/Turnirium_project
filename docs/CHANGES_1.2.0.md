# Turnirium 1.2.0 — единый выпуск доработок 1.1.6–1.2.0

Версия **1.2.0** включает всё, что ранее вошло в 1.1.6 и 1.1.7, а также изменения интерфейса секретаря и распределения по площадкам в 1.2.0. Это **полный релиз**, а не дополнение, которое нужно ставить поверх двух предыдущих архивов.

## Изменения 1.2.0

### Секретарь площадки

- **«Победа красного по счёту»**, **«Победа синего по счёту»** и **«Ничья»** (в форматах, где она допустима) сразу отправляют результат и завершают бой **одним нажатием** — без дополнительной кнопки и без подтверждающего диалога.
- Кнопка **«Завершить бой»** присутствует только при ожидающей санкции, которая может привести к поражению: техническое поражение, поражение по предупреждениям, дисквалификация, выбытие и их сочетания. Это позволяет секретарю сначала отметить санкцию у каждого бойца, включая обоюдный исход, и только затем зафиксировать окончательный результат.
- На время отправки результата кнопки результата блокируются от повторных нажатий. Проверка корректности завершения остаётся в серверном сервисе; существующие API и события WebSocket используются без изменения протокола.

### Назначение площадок

- У категории и её групп вместо отдельных кнопок площадок и кнопки «Несколько площадок» осталась **одна кнопка «Распределить по площадкам»**.
- В выпадающем списке можно отметить **одну или несколько** включённых площадок и нажать **«Подтвердить распределение»**.
- **Одна площадка**: сервер вызывает тот же алгоритм, что и прежняя отдельная кнопка, включая порядок добавления в очередь и настройку разведения повторных выходов.
- **Несколько площадок**: сохраняется равномерная балансировка и учёт повторных выходов, введённые в 1.1.7.
- Выпадающий список по-прежнему вынесен в `document.body`, чтобы не обрезаться другими элементами и прокручиваемыми карточками.
- Для API `POST /api/tournaments/{id}/schedule-assign-multi` теперь допустим `area_ids` с **одним** ID; `[]` отклоняется валидацией, повторяющиеся ID отклоняются бизнес-логикой. Ответ `{assigned, areas}` не изменён. Старый `schedule-assign-unit` сохранён для совместимости.

## Возможности, вошедшие из 1.1.6 и 1.1.7

- **Группы + плей-офф:** из группы могут выйти все её участники.
- **Расписание:** бои не назначаются автоматически даже при одной площадке. Группы/категории распределяются по нескольким площадкам; очереди балансируются, а кнопку «Оптимизировать очереди» можно использовать во время турнира, в том числе для выравнивания загруженности площадок. Уже идущие, выбранные текущими и завершённые бои не переносятся.
- **Секретарь и таблицы:** поддержаны санкции обеим сторонам, обоюдные технические поражения, поражения по предупреждениям, дисквалификации и выбытия; обоюдный исход не создаёт победителя, но фактические очки в бою сохраняются и учитываются в таблицах. Завершённые бои можно исправлять с указанием обоюдных исходов.
- **Швейцарская система:** можно добавить новый тур в уже идущую категорию, не пересоздавая предыдущие результаты.
- **Досрочное завершение:** любую категорию можно завершить с отменой оставшихся боёв, рассчитав итоговые места по уже проведённым боям.

Подробнее о механике распределения и таблиц: [CHANGES_1.1.6.md](CHANGES_1.1.6.md) и [CHANGES_1.1.7.md](CHANGES_1.1.7.md).

## Совместимость и обновление

- Структура SQLite не менялась; **миграция БД не требуется**. Перед применением к рабочему турниру сделайте резервную копию БД.
- Полный ZIP исходников 1.2.0 можно использовать вместо предыдущих архивов; не нужно поверх него применять патчи.
- Для перехода с исходников **1.1.7** примените `Turnirium_1.1.7_to_1.2.0.patch`.
- Для прямого перехода с исходных **1.1.5** (архив с GitHub, до любых наших изменений) примените **только** `Turnirium_1.1.5_to_1.2.0.patch`. Не применяйте оба патча последовательно.

```bash
git apply --check /путь/к/Turnirium_1.1.7_to_1.2.0.patch
git apply /путь/к/Turnirium_1.1.7_to_1.2.0.patch
```

Для прямого перехода с 1.1.5 используйте в командах имя накопительного патча. Обе версии патча проверяются применением к чистой распаковке соответствующей базовой версии и побайтовым сравнением полученных файлов с архивом 1.2.0.

## Проверки

```bash
python -m pytest -q -W error
python -m compileall -q app tests
for file in app/static/*.js; do node --check "$file"; done
```

В новую регрессию включены: эквивалентность одиночного назначения прежней кнопке, единичный выбор группы, валидация пустого/повторного выбора, мгновенное завершение по счёту и ничьей. Интерфейс секретаря и мультиселект дополнительно проверены в Chromium на тестовых данных. При обновлении рабочего турнира рекомендуется провести короткую ручную приёмку на тестовой базе.
