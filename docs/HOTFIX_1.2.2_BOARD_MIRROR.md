# Turnirium 1.2.2 — хотфикс зеркалирования зрительского табло

Исправление **поверх 1.2.2**, без повышения версии приложения. За основу взята 1.2.1 с применённым патчем `1.2.1 → 1.2.2`.

## Симптом

Секретарь может менять переключатель «Отзеркалить табло», API сохраняет `board_mirrored`, но экран уже открытого зрительского табло продолжает показывать прежний порядок красной и синей сторон. При этом время и счёт обновляются.

## Причина и исправление

В 1.2.2 браузер получал `/static/board.js`, `/static/secretary.js` и CSS по неизменным адресам, без привязки к фактической сборке. После обновления 1.2.1 → 1.2.2 могла остаться уже загруженная вкладка с прежним JS, который не умеет интерпретировать новый признак зеркалирования. Ранее имевшиеся тесты проверяли корректность нового `renderBoard`, но не проверяли загрузку актуальных ресурсов и работу давно открытого табло.

Исправлено:

- Хеш содержимого CSS и JS формируется при запуске. Каждый SPA-экран использует ссылки вида `/static/board.js?v=<хеш>` и `/static/...css?v=<хеш>`.
- HTML страниц выдаётся с `Cache-Control: no-store`, чтобы новое открытие экрана получило правильные URL ресурсов.
- `GET /api/areas/{area_id}/state` дополнен `frontend_revision`. Открытое **обновлённое** табло автоматически перезагружается, если сервер после последующего обновления запущен с другими файлами интерфейса.
- Событие `area_changed` с `board_mirrored` немедленно отражается на зрительском табло, без ожидания ответа API; периодическая синхронизация осталась.
- Устранена возможность, что запоздавший ответ HTTP возвратит старую ориентацию после переключения.
- Секретарь видит уведомление об успешно сохранённой ориентации и ошибку при неуспехе.
- Логические красная и синяя стороны боя, счёт, предупреждения, результаты, таймер и SQLite не меняются.

**Ограничение одноразового перехода:** вкладка зрительского табло, уже открытая на старом коде 1.2.1/первоначальном 1.2.2, не может автоматически выполнить проверку версии — такого механизма в старом JS не было. **После установки хотфикса один раз обновите страницу зрительского табло (Ctrl+F5 / F5).** Для последующих обновлений вкладка с хотфиксом сама обнаружит несовпадение ревизий и перезагрузится.

## Установка

Остановить Turnirium и сохранить резервную копию папки данных/базы SQLite. Применить `Turnirium_1.2.2_board_mirror_hotfix.patch` к исходникам **1.2.2 без предыдущего хотфикса** или заменить исходники из полного архива. Запустить приложение и **один раз перезагрузить открытое зрительское табло**.

```bash
git apply --check Turnirium_1.2.2_board_mirror_hotfix.patch
git apply Turnirium_1.2.2_board_mirror_hotfix.patch
```

Никакой новой миграции базы данных нет. Версия остаётся **1.2.2**. Патч включает регрессионные тесты и эту инструкцию.

## Проверки

```bash
python -m pytest -q -W error
python -m compileall -q app tests
for f in app/static/*.js; do node --check "$f"; done
```

Дополнительно в Chromium проверено фактическое визуальное расположение обеих сторон и следующего боя в режимах `false → true → false` со стилями приложения. HTTP-верификация выполнена тестовым клиентом FastAPI; полноценная проверка с удалённым устройством и реальным экраном не проводилась.
