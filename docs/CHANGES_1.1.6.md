# Turnirium 1.1.6 — исходники и патч к 1.1.5

Этот выпуск основан на исходном ZIP проекта версии **1.1.5**. Изменения не требуют миграции структуры существующей SQLite-БД: новые отметки технического поражения сохраняются как существующие записи `MatchEvent`, остальные доработки используют текущие таблицы.

## Новые возможности

1. **Группы + плей-офф.** Разрешено выбрать число выходящих из группы, равное её полному составу. Проверка по-прежнему запрещает выбирать больше участников, чем находится в группе.
2. **Планирование площадок.** Бои остаются без назначения независимо от числа созданных площадок. Даже при одной площадке организатор назначает их явно, отдельно от формирования сетки.
3. **Несколько площадок.** В быстром распределении категории и каждой группы есть кнопка «Несколько площадок». Она открывает выбор площадок с флажками и кнопкой «Распределить». Назначаются только готовые и ещё не назначенные бои; начатые бои и чужие очереди не перемещаются. Алгоритм балансирует длины очередей и старается не ставить одного бойца одновременно/подряд на разных площадках. Для оценки времени используется **позиция в очереди**, а не точное расписание по часам; при изменении фактической продолжительности поединков организатор может дополнительно скорректировать порядок вручную.
4. **Секретарь.** Техническое поражение можно независимо отметить и снять для каждой стороны. Предупреждения и накопленная дисквалификация также сначала фиксируются как санкции, но не завершают текущий бой. При нажатии **«Завершить бой»** сервер проверяет соответствие результата санкциям. При санкции обеим сторонам используется результат `DOUBLE_FORFEIT` (без победителя), а не ничья. В таблице обоим засчитывается поражение. Для олимпийской сетки отсутствие победителя учитывается при продвижении по сетке.
5. **Swiss.** После формирования первого тура можно увеличить лимит швейцарских туров кнопкой «+ Добавить Swiss-тур», не сбрасывая пары и результаты проведённых туров. Следующий тур формируется отдельным штатным действием после окончания текущего. Верхний лимит — 50 туров.
6. **Досрочное завершение.** Категорию любого формата можно завершить до проведения всех боёв с явным подтверждением. Незавершённые бои получают статус `cancelled`, предварительные счёт/санкции из этих боёв исключаются, а готовые результаты сохраняются. Итоговая таблица досрочно завершённой категории рассчитывается **по реально завершённым боям**, без зачёта неразыгранных проходов BYE. При повторном открытии категории отменённые бои возвращаются в рабочие статусы, но не автоматически назначаются на площадки.

## Основные файлы

- `app/services/schedule_distribution.py` — балансировка по выбранным площадкам.
- `app/services/match_penalties.py` — санкции, ожидающие подтверждения результата.
- `app/services/category_lifecycle.py` — отмена незавершённых и восстановление категории.
- `app/services/standings.py`, `app/services/brackets.py`, `app/services/matches.py` — зачёт, сетки и завершение боёв.
- `app/routes/` — проверка входных данных, новые API и аудит.
- `app/static/categories.js`, `schedule.js`, `secretary.js` и CSS — интерфейс.
- `tests/test_extended_tournament_rules.py` — новые интеграционные регрессии.

## API

- `POST /api/tournaments/{tournament_id}/schedule-assign-multi` — `{"category_id": 1, "group_name": "", "area_ids": [1, 2]}`. Для выбора одной конкретной группы указать её имя; `group_name` можно опустить для всей категории.
- `POST /api/categories/{category_id}/swiss-add-round` — увеличить лимит туров на 1. Уже состоявшиеся пары/результаты не меняются.
- `POST /api/categories/{category_id}/complete` — `{"cancel_unfinished": true}` для досрочного завершения. Если в категории остались незавершённые бои, без явного флага сервер вернёт HTTP 409.
- `POST /api/matches/{match_id}/technical-loss` — `{"side": "red"}` или `{"side": "blue"}`; повторный вызов для той же стороны снимает отметку.
- `POST /api/matches/{match_id}/finish` — при санкциях обеим сторонам `{"reason": "DOUBLE_FORFEIT", "winner_cp_id": null}`. Итог фиксируется только этим запросом.

## Применение патча

В каталоге **исходной версии 1.1.5** (в корне, где находятся `app/` и `tests/`):

```bash
git apply --check /путь/к/Turnirium_1.1.5_to_1.1.6.patch
git apply /путь/к/Turnirium_1.1.5_to_1.1.6.patch
```

Для проекта, скачанного ZIP без `.git`, можно использовать `git apply` даже без репозитория; при отсутствии Git подойдёт `patch -p1 < Turnirium_1.1.5_to_1.1.6.patch` (кроме особых случаев бинарных изменений; этот патч состоит из текстовых файлов).

Полный ZIP исходников — альтернативный способ получить ту же версию **1.1.6**, а не дополнительный этап после патча. Накатывать патч поверх архива 1.1.6 не нужно.

## Проверки

```bash
python -m pytest -q -W error
python -m compileall -q app tests
for f in app/static/*.js; do node --check "$f"; done
```

Перед применением на рабочей базе рекомендуется сделать резервную копию и вручную проверить переходы по олимпийской сетке и работу секретаря на тестовом турнире. Графический интерфейс не подвергался отдельному E2E-тестированию реальным браузером, поэтому автоматические тесты не заменяют такой приёмки.
