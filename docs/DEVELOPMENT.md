# Разработка Turnirium

## Локальный запуск

```bash
python run.py
```

Тесты и базовые проверки:

```bash
pytest -q
pytest -q -W error
python -m compileall -q app tests
for f in app/static/*.js; do node --check "$f"; done
```

## Стиль кода

- Комментарии и внутренние поясняющие docstring пишутся на русском языке.
- Имена Python/JavaScript-сущностей остаются английскими и должны описывать назначение, а не детали реализации.
- Один модуль отвечает за одну предметную область.
- Не размещать бизнес-алгоритмы в FastAPI-маршрутах.
- Не дублировать правила доверия между UI и сервером: UI помогает пользователю, сервер остаётся окончательной границей валидации.
- Избегать `except Exception`, кроме инфраструктурных границ, где требуется гарантированная очистка/диагностика или преобразование ошибки в контролируемый ответ.
- Составная операция должна либо фиксироваться целиком, либо полностью откатываться. Не делать внутренний `commit`, если сервис вызывается как часть более крупной транзакции.
- Изменение результата уже проведённого боя должно учитывать зависимые этапы; обходить проверки ради удобства UI нельзя.

## Добавление нового формата турнира

1. Добавить значение формата во входную схему и модель данных, если требуется.
2. Реализовать генерацию в отдельном сервисном модуле.
3. Добавить расчёт таблицы/мест в `services/standings.py`.
4. Подключить минимальные HTTP-вызовы в `routes/category_stages.py` и при необходимости CRUD в `routes/categories.py`.
5. Добавить UI формы и визуализацию в `static/categories.js`.
6. Добавить тесты генерации, результата, перестройки до первого боя, итогового ранжирования и экспорта.

## Изменение правил боя

Правила счёта и предупреждений проверяются сервером. Изменение счёта должно присутствовать в `score_buttons` категории; произвольный `delta` через API не принимается. Причины завершения ограничены известным набором, а ничья допустима только в форматах, где она предусмотрена.

## Импорт и массовые операции

Парсер сначала должен полностью проверить входные данные, а затем выполнять изменения одной транзакцией. Если одна строка делает операцию недопустимой, нельзя оставлять в БД результаты предыдущих строк этого же импорта.

## Версионирование

`app/version.py` — единый источник версии. Windows BAT-сборка получает из него `major.minor` и формирует имя вида `Turnirium_1.1.exe`.

## Перед выпуском

Обязательный автоматический прогон:

```bash
pytest -q
pytest -q -W error
python -m compileall -q app tests
for f in app/static/*.js; do node --check "$f"; done
```

Архитектурные и статические smoke-тесты входят в обычный `pytest` и должны оставаться включёнными.

Дополнительно вручную проверить на целевой Windows-сборке: создание турнира, категорию каждого формата, старт/завершение боя, блокировку перехода секретаря до результата, корректировку результата, экспорт, переключение БД, окно/трей и фирменную иконку.
