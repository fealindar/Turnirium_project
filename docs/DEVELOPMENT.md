# Разработка Turnirium

## Запуск

```bash
pip install -r requirements.txt
python run.py
```

Сервер без desktop-оболочки:

```bash
python run.py --server-only
```

## Тесты

Перед выпуском выполняются:

```bash
pytest -q
pytest -q -W error
python -m compileall -q app tests
for f in app/static/*.js; do node --check "$f"; done
```

## Правила изменений

- Бизнес-логику держать в `app/services/`, а не в HTTP-маршрутах или JavaScript.
- Проверки, влияющие на целостность турнира, должны выполняться на сервере. UI может дублировать их только для удобства.
- Массовые операции и импорт выполнять одной транзакцией.
- Не менять результат проведённого боя в обход механизма корректировки.
- При изменении схемы SQLite учитывать существующие локальные базы.
- Комментарии в исходниках писать по-русски; имена функций и переменных оставлять предметными и английскими.

## Frontend

Организатор — единая широкая рабочая область. Не вводить отдельную ширину страницы для каждой вкладки. Ограничивать ширину имеет смысл только у локальных элементов: форм, диалогов и небольших панелей.

Для широких таблиц, сеток и списка площадок использовать внутреннюю прокрутку. Не создавать горизонтальный скролл у всей страницы.

Состояние раскрытых элементов, выбранных вкладок и других локальных UI-контролов не должно теряться при WebSocket-перерисовке.


## Версия

Версия приложения хранится в `app/version.py`. Для исправлений без изменения формата данных увеличивается patch-номер.

Windows-сборка берёт версию из этого файла автоматически.

## Перед ручным релизом

Проверить хотя бы один турнир от создания до завершения:

1. добавить участников и категории;
2. сформировать каждый используемый формат;
3. назначить бои на несколько площадок;
4. провести бой через экран секретаря;
5. проверить табло и общий экран;
6. исправить завершённый результат;
7. проверить экспорт, резервную копию и повторное открытие БД.
